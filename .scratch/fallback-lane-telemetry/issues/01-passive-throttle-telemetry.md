# 01 — Passive throttle telemetry

**Status:** resolved
**Type:** code
**Category:** enhancement
**Blocked by:** —

## Context

The proxy already detects every degradation signature: thread-rate throttle
empties spanning distinct conversations (F13), per-conversation at-limit caps,
Disengaged frames, and the degradation-backoff state machine
(`noteRequestOutcome` / `getDegradationBackoffState` in `@m365-copilot/core`;
detection sites in `packages/proxy-lib/src/handler.ts`). Nothing persists
these events. This ticket logs them so the fallback-lane decision has data.

## Change

1. Emit structured NDJSON events to
   `~/.config/opencode-m365/throttle-telemetry.ndjson` (path env-overridable;
   `M365_NO_TELEMETRY=1` disables; file stays OUTSIDE the repo — repo is
   public).
2. Event types, at the existing detection sites (no new request logic):
   - `empty-throttle` — `noteRequestOutcome(true, convId)` signature
   - `backoff-enter` / `backoff-exit` — level, `backoffUntil`, measured
     duration on exit
   - `disengaged` — framing used, retry outcome (F22 softened-retry or
     fail-fast)
   - `at-limit` — per-conversation cap (`t.current >= t.max`)
3. Fields: ISO timestamp, event, sha256-hashed convId (no raw ids), level,
   duration. No PII, no request bodies.
4. Extend `buildHealthPayload`'s existing `backoff` block with in-memory
   event counts since process start.
5. An event MUST never trigger or modify any M365 request.
