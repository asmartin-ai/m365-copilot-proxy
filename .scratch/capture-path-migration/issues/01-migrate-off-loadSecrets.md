# 01 — Migrate capture scripts off dead loadSecrets() to msal/persistent profile

**Status:** needs-triage
**Category:** bug
**Type:** code
**Blocked by:** —

## Context

The `m365-gui-capture.mjs` path (and its siblings: `gateway-capture.mjs`,
`studio-dig.mjs`, `cancel-frame-capture.mjs`, `gateway-explore.mjs`,
`create-full-bot.mjs`, `m365-gui-emulate.mjs`, `throttle-recovery-ab.mjs`,
`login-probe.mjs`, `da-app/sideload-*.mjs`) all `import { loadSecrets }` from
`../packages/core/dist/index.mjs` and do their own manual Playwright login with
`creds.password` / `creds.mfaSecret`.

**`loadSecrets` does not exist in core — source or dist.** Verified 2026-08-11:

- `grep loadSecrets packages/core/src` → no matches
- `grep loadSecrets packages/core/dist/index.mjs` → no matches
- `~/.config/opencode-m365/secrets.json` does not exist
- Every script that calls `loadSecrets()` crashes at import time:
  `SyntaxError: The requested module '.../dist/index.mjs' does not provide an
  export named 'loadSecrets'`

## Root cause

The repo migrated auth from a **password/MFA `secrets.json` flow** to an
**MSAL token cache** (`~/.config/opencode-m365/msal-cache.json`) + a
**Playwright persistent profile** (`browser-profile-cdp`). The capture scripts
were never migrated — they still call the dead secrets API and re-implement
password login. Fallout of the password→MSAL refactor.

## Working (modern) path — proved live 2026-08-11

- `getTokenSilent()` from the msal cache returns a live token:
  `<account-email>`, oid `<oid>` (verified via
  `node -e` against `dist/index.mjs`)
- `loginInteractive()` in `packages/core/src/auth.ts` drives Playwright with
  `chromium.launchPersistentContext(getBrowserProfileDir(), { headless: false })`
  — the persistent profile stays logged in; code is scraped from the
  nativeclient redirect (`extractAuthCode`), **no password in the script**
- `getBrowserProfileDir()` → `browser-profile-cdp` (has Login Data + account)

## What to do

1. Rewrite `m365-gui-capture.mjs` (the primary GUI-frame capture) to:
   - Drop `loadSecrets` entirely.
   - Launch the browser with `chromium.launchPersistentContext(getBrowserProfileDir(), { headless: false })` so it comes up **already logged in** from the persistent profile.
   - Keep the WebSocket frame capture (optionsSets / variants / tone / agent
     payload diff) — that is the whole point of the script.
   - Fall back to `loginInteractive()` only if the persistent profile is
     signed out, instead of manual password filling.
2. Sweep the sibling scripts (`gateway-capture`, `studio-dig`,
   `cancel-frame-capture`, `gateway-explore`, `create-full-bot`,
   `m365-gui-emulate`, `throttle-recovery-ab`, `login-probe`, `da-app/*`)
   and apply the same migration (drop `loadSecrets`, use the msal
   token/persistent profile).
3. Delete `loadSecrets`-specific error handling / "no secrets" exit paths.
